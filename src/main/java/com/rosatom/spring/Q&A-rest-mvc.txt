MVC:
- Что такое паттерн MVC и для чего он нужен?
архитектурный паттерн, используемый в разработке программного
обеспечения для разделения приложения на три основных компонента:
Model (Модель): хранение данных и бизнес-логику приложения.
    Модель предоставляет данные, которые могут быть отображены
    в пользовательском интерфейсе (View) и обрабатывает все операции
    над этими данными.
View (Представление): View отвечает за отображение данных пользователю и
    предоставляет интерфейс для взаимодействия с приложением. Он не содержит
    бизнес-логики, а просто отображает данные, предоставленные Model.
Controller (Контроллер): Контроллер принимает пользовательские запросы,
    обрабатывает их, взаимодействует с Model для получения необходимых данных
    и передает эти данные в View для отображения пользователю. Он является
     посредником между Model и View.
Такая архитектура позволяет легко поддерживать и расширять приложение,
 разделяя его на логические компоненты с четкими обязанностями.



- Как бы вы связали Spring MVC Framework и архитектуру MVC?
Spring MVC Framework - это часть Spring Framework, которая реализует
архитектуру MVC. Spring MVC связывает эти компоненты следующим образом:



- Что такое контроллер в Spring MVC?
В Spring MVC контроллер (Controller) - это компонент, который
обрабатывает входящие HTTP-запросы от клиентов. Контроллеры обычно
 аннотируются с помощью @Controller и содержат методы-обработчики,
 которые принимают запросы, взаимодействуют с моделью и возвращают представления.



- Расскажите, что вы знаете о DispatcherServlet и ContextLoaderListener.
DispatcherServlet - это основной компонент Spring MVC, который принимает
    входящие HTTP-запросы и определяет, какой контроллер должен
    обработать запрос. DispatcherServlet связывается с конфигурацией
    Spring MVC (например, через WebApplicationContext), чтобы найти
    соответствующий контроллер и выполнить метод обработчика.
ContextLoaderListener - это другой компонент Spring, который используется
    для загрузки корневого контекста Spring приложения. Он обычно используется
    для настройки служб, которые могут быть доступны всему приложению, а
    не только для части, связанной с веб-службами.



- Что такое DispatcherServlet и где он используется?
DispatcherServlet - это компонент Spring MVC, который используется
 для обработки входящих HTTP-запросов. Он определяет, какой контроллер
 должен обработать запрос и управляет циклом обработки запроса.
 DispatcherServlet используется в веб-приложениях на Spring MVC.




- Какой жизненный цикл у запроса?
Жизненный цикл запроса в Spring MVC включает в себя следующие этапы:
входящий HTTP-запрос, обработка контроллером, взаимодействие с моделью,
выбор представления и отправка HTTP-ответа клиенту.



https://stackoverflow.com/questions/49819633/spring-singleton-scope-vs-application-scope
- Что такое WebApplicationContext? Какие дополнительные скоупы он привносит?
WebApplicationContext - это контекст Spring, предназначенный для
управления компонентами веб-приложения. Он вводит дополнительные скоупы,
такие как request, session и application, чтобы управлять бинами в
течение жизненного цикла HTTP-запроса.



- Зачем нужен session scope?
хранить бины в течение сессии пользователя. Это полезно, когда
нужно сохранять данные между разными запросами одного и того же
пользователя, например, для хранения состояния во время его
взаимодействия с приложением.




- Зачем используется аннотация @Controller?
для пометки классов в Spring MVC как контроллеров.
Это позволяет Spring узнать, что данный класс обрабатывает HTTP-запросы
и содержит методы-обработчики для них.



- Как входящие запросы сопоставляются с методами-обработчиками?
В Spring MVC, входящие HTTP-запросы сопоставляются с методами-обработчиками
    (методами контроллера) на основе URL-пути и HTTP-метода запроса.
    Это сопоставление выполняется с использованием аннотаций, таких как
    @RequestMapping, @GetMapping, @PostMapping и других, которые определяют,
     какой метод контроллера должен обрабатывать определенный запрос.



- Расскажите про аннотацию @RequestMapping
это аннотация, которая позволяет определить URL-путь и HTTP-метод,
который будет обрабатываться методом контроллера. Например,
@RequestMapping(value = "/products", method = RequestMethod.GET)
означает, что метод контроллера обработает GET-запросы по пути "/products".



- Что за аннотации @GetMapping, @PostMapping, @DeleteMapping и прочие?
@GetMapping, @PostMapping, @DeleteMapping и другие
аннотации являются сокращенными формами @RequestMapping.
Они позволяют определить, какой HTTP-метод должен обрабатываться
методом контроллера. Например, @GetMapping("/products") эквивалентен
 @RequestMapping(value = "/products", method = RequestMethod.GET).




- Зачем используется аннотация @RequestParam?
извлечения параметров запроса из URL-строки и передачи их методу контроллера.
Например, @RequestParam("id") int productId позволяет извлечь параметр
"id" из URL и передать его в метод контроллера в качестве аргумента.




- Зачем нужна аннотация @PathVariable?
@PathVariable используется для извлечения переменных из URL-пути.
Например, @GetMapping("/products/{id}") и @PathVariable("id")
int productId позволяют извлечь значение "id" из URL-пути
и передать его в метод контроллера.




- Какие параметры могут принимать методы-обработчики?
@RequestParam, @PathVariable, @RequestBody




- Какие еще существуют аннотации для использования рядом с параметрами метода?
@RequestHeader (извлечение заголовков запроса),
@ModelAttribute (получение объектов модели),
@SessionAttribute (работа с атрибутами сессии) и другие.



- Что за аннотация @RequestBody?
@RequestBody используется для преобразования тела
HTTP-запроса в объект Java (например, JSON в объект Java).




- Что может возвращать метод контроллера?
String (имя представления),
void (без ответа),
ResponseEntity (для полного контроля над HTTP-ответом) и другие.




- Что такое View?
часть, которая отвечает за отображение данных пользователю.
Он представляет собой шаблон или страницу, в которую встраиваются
данные из Model. View отображает информацию, предоставленную
контроллером, и предоставляет пользовательский интерфейс
для взаимодействия с приложением.




- Как выбирается View в фазе рендеринга? Как отображается View?
View выбирается на основе имени, возвращаемого методом контроллера.
Имя представления передается из метода контроллера, и
Spring MVC использует ViewResolver для нахождения и
отображения соответствующего представления.
ViewResolver может преобразовать имя представления в реальный шаблон,
который будет использоваться для отображения данных, и затем данные
из Model передаются в это представление для рендеринга.




- Что такое Model?
контейнер для данных, которые будут отображены в представлении (View).
Он передается от контроллера к представлению и используется для передачи
информации от бизнес-логики (Model) к пользовательскому интерфейсу (View).




- Что такое ViewResolver в Spring?
 компонент, который отвечает за поиск и определение,
 какой конкретный представление (View) должно быть использовано
 для отображения данных в ответ на запрос.
 ViewResolver преобразует имя представления,
 возвращаемое контрроллером, в реальный шаблон или представление.




- В чем разница между Filters, Listeners and Interceptors?
Filters - это часть стандарта Java Servlet API, которая используется
    для обработки запросов и ответов до того, как они достигнут сервлета.
    Filters применяются ко всем запросам и могут выполнять различные операции,
    такие как аутентификация, логирование и изменение запросов.
Listeners - это также часть стандарта Java Servlet API, и они используются
    для прослушивания событий жизненного цикла сервлетов и веб-приложения.
    Listeners позволяют реагировать на события, такие как запуск и завершение
    приложения.
Interceptors - это часть Spring MVC и позволяют выполнять
    дополнительные операции до и после выполнения методов контроллера.
    Они применяются к запросам, обработанным Spring MVC, и обеспечивают
    гибкую обработку запросов и ответов.



- В чем разница между ModelMap и ModelAndView?
ModelMap - это объект, используемый для хранения данных Model в
    Spring MVC. Он представляет собой простой контейнер для данных,
    которые будут переданы в представление.
ModelAndView - это класс, который объединяет Model и View.
    Он предоставляет возможность указать как данные Model, так
    и имя представления (View) вместе в одном объекте.




- В чем разница между model.put() и model.addAttribute()?
Оба метода добавляют атрибуты в Model



- Что можете рассказать про Form Binding?
процесс связывания данных, введенных пользователем в HTML-формах,
с объектами Java (как правило, объектами модели) в Spring MVC.



- Где должны располагаться статические (css, js, html) ресурсы в Spring MVC приложении?
в папке "resources" или "static" внутри директории веб-приложения.
Spring MVC автоматически обслуживает эти статические ресурсы и может
использовать их для отображения на страницах представления.




- Что такое MultipartResolver и когда его использовать?
компонент Spring MVC, используемый для обработки многочастных
HTTP-запросов, например, для загрузки файлов. Его следует использовать,
когда вам нужно обрабатывать формы, включающие загрузку файлов на сервер.




- Как загрузить файл в Spring MVC?
MultipartResolver и аннотацию @RequestParam для обработки
файлов в методах контроллера. Пример:
@PostMapping("/upload")
public String uploadFile(@RequestParam("file") MultipartFile file) {
    // Обработка загруженного файла
    // file.getBytes() позволяет получить содержимое файла
    return "redirect:/success"; // Вернуть на страницу успеха
}




- Как обрабатывать исключения в Spring MVC Framework?
использовать аннотацию @ControllerAdvice для создания глобального
обработчика исключений. В этом классе вы можете определить методы для
обработки конкретных исключений, которые могут возникнуть в вашем приложении.
Также можно использовать аннотацию @ExceptionHandler для обработки исключений
внутри отдельных контроллеров.




- Каковы минимальные настройки, чтобы создать приложение Spring MVC?
Конфигурационный класс, настроенный с помощью аннотации @EnableWebMvc.
Контроллеры, определенные с использованием аннотации @Controller.
Представления (View) и ViewResolver для отображения данных.
WebApplicationContext для управления бинами веб-приложения.




- Как добиться локализации в приложениях Spring MVC?
 настройку интернационализации с использованием файлов свойств (.properties)
 для каждого поддерживаемого языка и использование классов LocaleResolver
 для выбора языка пользователя.



- Как проверить (валидировать) данные формы в Spring Web MVC Framework?
нужно аннотировать поля объекта модели, представляющего форму,
с аннотациями, такими как @NotNull, @Size, @Pattern, и другими.
Затем вы можете использовать аннотацию @Valid в методе контроллера,
чтобы активировать валидацию. Ошибки валидации будут автоматически добавлены
в объект BindingResult, который вы можете проверить в методе контроллера.




- Что вы знаете Spring MVC Interceptor и как он используется?
компонент, который позволяет выполнить дополнительные операции
до и после выполнения методов контроллера. Они предоставляют механизм
для выполнения общих задач, таких как аутентификация, проверка доступа,
логирование и другие.



- Почему для конфиденциальных данных рекомендуется использовать POST, а не GET запросы?
Рекомендация использовать POST запросы для конфиденциальных данных обусловлена тем
, что данные, отправленные в URL через GET запрос, видны в адресной строке
браузера и могут быть записаны в журналах сервера. В случае POST запроса,
данные передаются в теле HTTP-запроса и обычно не отображаются в адресной строке.
 Это делает POST более безопасным для передачи конфиденциальных данных,
 таких как пароли или данные кредитных карт.






REST:
- Как мы можем использовать Spring для создания REST-сервиса, возвращающего JSON?
ля создания REST-сервиса, возвращающего JSON в Spring, вы можете использовать
аннотации @RestController. Методы контроллера, помеченные @RestController,
автоматически возвращают данные в формате JSON. Вы также можете использовать
@RequestMapping или более специфические аннотации, такие как
@GetMapping и @PostMapping, для определения URL-путей и HTTP-методов,
которые обрабатываются.




- В чём разница между @Controller и @RestController?
@Controller используется для создания обычных контроллеров в Spring MVC,
которые возвращают HTML представления. @RestController - это специализированная
версия @Controller, предназначенная для создания REST-контроллеров,
которые возвращают данные в формате JSON или других форматах,
а не HTML представления.




- Как работает аннотация @RestController?
@RestController комбинирует функциональность аннотации @Controller и @ResponseBody.
Он автоматически сериализует возвращаемые объекты в формат JSON и
отправляет их в ответ на HTTP-запросы.




- Что обозначают разные коды для http-ответов?
Разные HTTP-коды состояния указывают на результат выполнения HTTP-запроса.
Например, код 200 (OK) означает успешный запрос, а код 404 (Not Found)
указывает на то, что запрошенный ресурс не найден.
HTTP-коды используются для информирования клиента о результате запроса.




- Зачем нужна аннотация @ResponseStatus?
используется для установки кода состояния HTTP-ответа, который будет отправлен
клиенту при выполнении метода контроллера. Это позволяет явно определить
код состояния, который следует вернуть, вместо использования значения по умолчанию.




- Что такое ResponseEntity?
класс Spring, который позволяет полностью управлять HTTP-ответом.
Он позволяет установить код состояния, заголовки и тело ответа.
Это полезно, когда вам нужно более тонкое управление над HTTP-ответом.



- Что такое RestTemplate? Какие у него преимущества?
kласс в Spring, который облегчает взаимодействие с удаленными REST-сервисами.
Он предоставляет методы для выполнения HTTP-запросов к удаленным ресурсам
и обработки ответов. Преимущества включают удобство в использовании,
обработку ошибок и поддержку разных методов HTTP.



- Можем ли мы послать объект как ответ метода обработчика контроллера?
Да, вы можете отправлять объекты в качестве ответов методов контроллера,
и они будут автоматически сериализованы в формат JSON,
если контроллер помечен аннотацией @RestController.
В противном случае, вам потребуется использовать представление
для отображения данных.




- Зачем нужна @ResponseBody?
@ResponseBody указывает, что возвращаемое значение метода
контроллера должно быть отправлено в теле HTTP-ответа,
а не отображено в представлении.
Это полезно при создании REST-сервисов, где данные должны быть
возвращены в формате JSON или других форматах.




- Почему иногда мы используем @ResponseBody, а иногда ResponseEntity?
@ResponseBody используется, когда вам нужно просто вернуть данные
в теле HTTP-ответа, и Spring автоматически сериализует их в JSON.
ResponseEntity предоставляет больше гибкости, позволяя вам установить
код состояния, заголовки и тело ответа вручную.




- Для чего был создан REST?
REST (Representational State Transfer) был создан для проектирования
архитектурных стилей взаимодействия между клиентом и сервером.
Он обеспечивает унифицированный и гибкий способ доступа
к веб-ресурсам через стандартные HTTP-методы, такие как GET, POST, PUT и DELETE.



- Что такое ресурс?
ресурс - это любой объект или информация, которую клиент может
запросить или изменить.
Ресурсы могут быть представлены URL и могут быть как статичными данными,
так и динамически созданными, например, через API.



- Что обозначает CRUD?
"Create, Read, Update, Delete".
Это основные операции, которые могут быть выполнены с данными,
и они соответствуют стандартным HTTP-методам:
POST (Create), GET (Read), PUT (Update), и DELETE (Delete).



- REST безопасен? Как вы можете защитить его?
Безопасность REST-сервисов зависит от множества факторов,
включая авторизацию и аутентификацию пользователей, защиту от атак,
ограничение доступа к ресурсам и другие меры безопасности.
Для защиты REST-сервисов вы можете использовать токены аутентификации,
HTTPS, правильную настройку доступа и другие методы.


- Что такое save operations?
"Save operations" обычно относится к операциям, которые сохраняют
 (создают или обновляют) данные на сервере или в базе данных.
 В контексте REST, это может включать в себя HTTP-запросы
 GET, HEAD,

- Что такое идемпотентая операция? Почему идемпотентность важна?
операция, которая может быть безопасно повторена многократно без
изменения состояния системы. Например, операции чтения
(GET) в REST являются идемпотентными, так как они не меняют
 состояние сервера. Это важно, потому что идемпотентность
 обеспечивает безопасность и надежность при обработке запросов,
 которые могут повторяться.



- REST хорошо масштабируется?
REST хорошо масштабируется и может быть развернут в распределенных системах.
RESTful архитектура поддерживает принципы горизонтального масштабирования,
 и многие веб-сервисы масштабируются путем добавления новых серверов и
балансировки нагрузки.
REST также работает хорошо с кэшированием, что способствует увеличению
производительности.
