- Расскажите о Spring Security
мощный и гибкий фреймворк для обеспечения безопасности в приложениях на платформе Java.
Он предоставляет обширные средства для аутентификации,
авторизации, защиты от атак, управления сессиями



- Что такое аутентификация и авторизация?
Аутентификация - это процесс проверки подлинности пользователя,
    то есть установление того, что пользователь является тем, за кого он себя выдаёт.
Авторизация - это процесс установления прав доступа пользователя
    к определенным ресурсам или операциям после успешной аутентификации.




- Как Security работает внутри?
Spring Security внедряется в приложение с использованием
    фильтров и аспектов аспектно-ориентированного программирования (AOP).
Он предоставляет цепочку фильтров для обработки запросов,
начиная с аутентификации и заканчивая авторизацией.
Основные компоненты включают AuthenticationManager,
UserDetailsService, UserDetails, и другие.
https://habr.com/ru/articles/203318/



- Основные объекты, участвующие в Spring Security
AuthenticationManager: Обрабатывает аутентификацию.
UserDetailsService: Предоставляет информацию о пользователе для аутентификации.
UserDetails: Представляет информацию о пользователе, включая его учетные данные и роли.
GrantedAuthority: Представляет роль или разрешение пользователя.



- Что такое делегирующий прокси фильтр?
DelegatingProxyFilter: Это фильтр, который делегирует обработку
запроса другим фильтрам в цепочке фильтров.



- Что такое security filter chain?
последовательность фильтров, предназначенных для обеспечения безопасности.
Они обрабатывают аутентификацию, авторизацию и другие задачи безопасности.



- Что такое security context?
объект, который содержит информацию об аутентификации текущего
пользователя, включая его принадлежность к ролям и другие данные.



- Как установить перехват перехода пользователя по определенным URL?
SecurityConfigurerAdapter для настройки перехвата переходов. Например:
http
    .authorizeRequests()
        .antMatchers("/secure/**").hasRole("ADMIN")
        .and()
    .formLogin()
        .loginPage("/login")
        .and()
    .logout()
        .logoutUrl("/logout");




- Что означает * в методах antMatchers и mvcMatchers()?
используется как шаблон для сопоставления любого количества символов
в указанном участке URL. Например, antMatchers("/admin/**")
сопоставит с любым URL, начинающимся с "/admin/".




- Почему mvcMatcher более защищенный чем antMatcher?
более высокоуровневый интерфейс для сопоставления URL,
который автоматически обрабатывает дополнительные условия,
такие как HTTP-методы и параметры.




- Spring поддерживает хэширование паролей? Что такое соль?
Spring Security поддерживает хэширование паролей.
Соль - это случайная строка, добавляемая к паролю перед хэшированием.




- Зачем нужна защита для методов? Как ее установить?
используется для определения прав доступа к отдельным методам в коде.
Ее можно установить, используя аннотации, такие как
@Secured, @RolesAllowed, @PreAuthorize, и другие.




- Что делает аннотация @RolesAllowed?
 позволяет указать роли, которые имеют доступ к методу.




- Расскажите про @PreAuthorize
более гибкий способ задания выражений для определения доступа к методу.
 Он позволяет использовать выражения на основе
 SpEL (Spring Expression Language) для определения условий доступа.



- Как реализованы все эти аннотации?
Аннотации для аутентификации и авторизации в Spring Security реализованы
с использованием аспектов AOP.
 Фреймворк создает прокси-объекты для классов,
 помеченных аннотациями, и внедряет соответствующую логику безопасности.



- Какие протоколы аутентификации вы знаете?
HTTP Basic, HTTP Digest, OAuth, OpenID Connect и SAML.



- Что такое OAuth 2.0?
протокол авторизации, который позволяет пользователям предоставлять
третьим сторонам ограниченный доступ к их ресурсам
без необходимости передачи своих учетных данных.




- Что такое LDAP-аутентификация?
LDAP (Lightweight Directory Access Protocol) - это протокол доступа
к каталогам, таким как каталог пользователей.
LDAP-аутентификация используется для проверки учетных данных
пользователей в каталоге LDAP. В Spring Security, вы можете
использовать LdapAuthenticationProvider для настройки аутентификации через LDAP.

Transaction:


транзакции управляются с использованием аннотации @Transactional
или через программное управление с использованием
TransactionTemplate или PlatformTransactionManager.



- Как сделать метод транзакционным?
использовать аннотацию @Transactional перед методом




- Что такое TransactionManager?
интерфейс в Spring, который определяет методы для управления транзакциями.
Конкретная реализация зависит от выбранного вами источника
 данных (например, DataSourceTransactionManager для JDBC).




- Что такое TransactionInterceptor?
аспект Spring, предоставляющий логику для управления
транзакциями с использованием аспектно-ориентированного программирования (AOP).




- Какие параметры есть у аннотации @Transactional?
@Transactional включают:
propagation
readOnly
isolation
timeout
rollbackFor
noRollbackFor



- Что означает параметр propagation?
 как транзакция должна вести себя в контексте уже существующей транзакции.



- Какие бывают propagation?
REQUIRED, REQUIRES_NEW, SUPPORTS, MANDATORY, NESTED, NOT_SUPPORTED, и NEVER.



- Что означает propagation MANDATORY?
метод требует активной транзакции и вызовет исключение, если транзакция отсутствует.



- Что означает propagation NESTED?
метод создает вложенную транзакцию, если активной транзакции нет.
Вложенная транзакция может быть сохранена или откатана независимо от внешней транзакции.



- Что означает propagation NEVER?
метод не должен выполняться в контексте активной
транзакции и вызовет исключение, если такая транзакция присутствует.



- Что означает propagation NOT_SUPPORTED?
метод не должен выполняться в контексте активной транзакции.
Если такая транзакция присутствует, она будет приостановлена до завершения метода.



- Что означает propagation REQUIRED?
 (по умолчанию) означает, что метод требует активной транзакции.
 Если транзакция уже существует, метод будет выполняться в ее контексте.

https://ru.stackoverflow.com/questions/87372/Уровень-изоляции-транзакций-и-hibernate

- Что означает propagation REQUIRES_NEW?
метод будет выполняться в новой транзакции, отдельной от текущей активной транзакции.



- Что означает propagation SUPPORTS?
метод поддерживает активную транзакцию, но не требует ее наличия.
Если транзакция существует, метод будет выполняться в ее контексте,
в противном случае - без транзакции.



- Что означает параметр readOnly?
 является ли транзакция только для чтения (true)
 или она может включать операции записи (false).



- Что означает параметр timeout?
максимальное время в секундах,
которое транзакция может оставаться активной, прежде чем будет вызван откат.



- Что означает параметр rollbackFor?
 указывает на класс(ы) исключений, при которых транзакция должна быть откачена.



- Что означает параметр isolation?
 определяет уровень изоляции транзакции от других параллельных транзакций.



- Какие бывают isolation?
DEFAULT,
READ_UNCOMMITED,
READ_COMMITED,
REPEATABLE_READ,
SERIALIZABLE


- Что означает isolation: DEFAULT, READ_UNCOMMITTED, READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE?
DEFAULT: Использует уровень изоляции по умолчанию для базы данных.
READ_UNCOMMITTED: позволяет транзакциям видеть изменения, которые еще не были зафиксированы другими транзакциями.
READ_COMMITTED: транзакция видит только те изменения, которые были зафиксированы (committed) другими транзакциями.
REPEATABLE_READ: транзакция видит одни и те же данные при каждом чтении в пределах транзакции.
SERIALIZABLE: никакие другие транзакции не могут одновременно вмешиваться в выполнение текущей транзакции.
Isolation Level defends:        Transactions    Dirty Reads    Non-Repeatable Reads    Phantom Reads
TRANSACTION_NONE                     -              -                   -                    -
TRANSACTION_READ_UNCOMMITTED         +              -                   -                    -
TRANSACTION_READ_COMMITTED           +              +                   -                    -
TRANSACTION_REPEATABLE_READ          +              +                   +                    -
TRANSACTION_SERIALIZABLE             +              +                   +                    +

Dirty Reads: пишем данные, читаем в другой транзакции, делаем rollback на запись.
Non-Repeatable Reads: читаем данные, обновляем их, читаем уже другие.
Phantom Reads: читаем данные, записываем новую, читаем снова уже больше.
