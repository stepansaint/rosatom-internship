- Расскажите о принципах SOLID
Принцип единственной ответственности (Single Responsibility Principle - SRP):
    Каждый класс должен иметь только одну причину для изменения.
    Класс должен быть ответственным только за один аспект функциональности.
Принцип открытости/закрытости (Open/Closed Principle - OCP):
    Программные сущности (классы, модули, функции) должны быть открыты для расширения и закрыты для модификации.
    Новая функциональность добавляется через расширение, а не изменение существующего кода.
Принцип подстановки Барбары Лисков (Liskov Substitution Principle - LSP):
    Объекты базового класса должны быть заменяемы объектами его производного класса без изменения корректности программы.
Принцип разделения интерфейса (Interface Segregation Principle - ISP):
    Клиенты не должны зависеть от интерфейсов, которые они не используют.
    Не следует создавать "толстые" интерфейсы, содержащие больше методов, чем нужно клиентам.
Принцип инверсии зависимостей (Dependency Inversion Principle - DIP):
    Модули верхнего уровня не должны зависеть от модулей нижнего уровня. Оба типа модулей должны зависеть от абстракций.
    Абстракции не должны зависеть от деталей. Детали должны зависеть от абстракций.



- Расскажите о шаблонах GRASP
General Responsibility Assignment Software Patterns:
Information Expert:
    Задачу следует поручить тому классу, у которого есть необходимая информация.
Creator:
    Объект A должен создавать объекты B, если объект A использует объекты B.
Controller:
    Задача контроллера - координировать обработку запросов и делегировать работу другим объектам.
Pure Fabrication:
    Создать класс, не представляющий концепцию в предметной области, если это улучшает структуру программы.
Indirection:
    Следует использовать промежуточный объект для связи между другими объектами, чтобы уменьшить зависимость между ними.
Polymorphism:
    Использовать полиморфизм для выполнения операций различными способами.



- Расскажите о шаблонах GoF
Шаблоны GoF (Gang of Four):
Шаблоны GoF подразделяются на три категории:
    порождающие, структурные и поведенческие шаблоны.



- Что такое поведенческие шаблоны?
Шаблоны, определяющие способы взаимодействия между объектами.
Примеры: Состояние, Наблюдатель, Стратегия, Шаблонный метод.



- Что такое порождающие шаблоны?
Порождающие шаблоны:
Шаблоны, отвечающие за создание объектов. Примеры: Фабричный метод, Абстрактная фабрика, Одиночка (Singleton).



- Что такое структурные шаблоны?
Структурные шаблоны:
Шаблоны, касающиеся композиции объектов и классов. Примеры: Адаптер, Мост, Прокси, Декоратор, Фасад.



- Расскажите о паттерне Singleton
Паттерн Singleton:
Гарантирует, что у класса есть только один экземпляр, и предоставляет глобальную точку доступа к этому экземпляру. Это полезно, когда нужен единственный объект для координации действий в системе.



- Расскажите о паттернах Фабричный метод и абстрактная фабрика
Фабричный метод (Factory Method):
Определяет интерфейс для создания объекта, но делегирует выбор типа объекта подклассам.
Абстрактная фабрика (Abstract Factory):
Предоставляет интерфейс для создания семейств взаимосвязанных или взаимозависимых объектов без указания их конкретных классов.



- Расскажите о паттерная адаптер и мост
Адаптер (Adapter):
Позволяет интерфейсу класса работать с другим интерфейсом.
Преобразует интерфейс класса к другому интерфейсу, который клиент ожидает.
Мост (Bridge):
Разделяет абстракцию от её реализации, чтобы оба могли изменяться независимо.


- Расскажите о паттерне Proxy
Паттерн Proxy предоставляет заменитель или заполнитель для другого объекта, чтобы контролировать доступ к нему или добавлять дополнительную логику.



- Расскажите о паттерне Декоратор
Позволяет динамически добавлять объектам новые обязанности, оборачивая их в специальные классы-декораторы.



- Расскажите о паттерне Шаблонный метод
Определяет скелет алгоритма в родительском классе, но оставляет определение некоторых шагов подклассам.



- Расскажите о паттерне Фасад
Предоставляет унифицированный интерфейс для группы интерфейсов в подсистеме, упрощая тем самым работу с этой подсистемой.



- Что такое рефакторинг? Объясните понятие "чистого" кода
Рефакторинг - это процесс улучшения структуры кода без изменения его внешнего поведения. Это позволяет улучшить читаемость, сопровождаемость, расширяемость и эффективность кода.

"Чистый" код:
"Чистый" код - это код, который легко читается, понимается и поддерживается. Он следует принципам простоты, эффективности и аккуратности. "Чистый" код обычно имеет небольшие функции, хорошо выбранные имена переменных, стройную структуру и отсутствие избыточности. "Чистый" код облегчает совместную разработку и поддержание программного обеспечения.












- Что такое UML?
(Unified Modeling Language):
UML (Unified Modeling Language) - это стандартный язык моделирования, который используется для визуализации, проектирования и документации программных систем. Он предоставляет нотацию и семантику для описания структуры и поведения систем.



- Что такое class diagram?
Диаграмма классов в UML используется для визуализации структуры системы в терминах классов и их взаимоотношений. Классы представляют сущности системы, а связи между классами отображают отношения между этими сущностями.



- Что такое sequence diagram?
Диаграмма последовательности в UML представляет собой визуализацию взаимодействия между объектами во времени. Она отображает порядок вызова методов и передачу сообщений между объектами в рамках определенной последовательности событий.



- Что такое use-case diagram?
Диаграмма вариантов использования в UML используется для описания функциональности системы с точки зрения внешних акторов (пользователей или других систем). Варианты использования представляют собой конкретные сценарии взаимодействия между акторами и системой.



- Что такое ER-diagram?
ER-диаграмма используется для моделирования сущностей и их взаимоотношений в базах данных. Сущности представляют объекты, а связи - отношения между этими объектами.




- Что такое Data Flow диаграмма?
Data Flow Диаграмма используется для визуализации потока данных в информационной системе. Она представляет собой графическое представление процессов, данных и потоков управления в системе.



- Что такое BPMN?
BPMN - это стандартная нотация для моделирования бизнес-процессов. Она предоставляет графическое представление шагов, ролей, активностей и потоков данных в рамках бизнес-процесса.



- Что такое IDEF?
IDEF - это семейство методологий и нотаций для моделирования бизнес-процессов и систем. Различные версии IDEF используются в различных областях, таких как инженерия производства, системная интеграция и другие.












- Расскажите о паттерне Inversion of Control (IoC) и его реализациях
Inversion of Control (IoC) - это принцип, при котором контроль над потоком выполнения переходит от программы к фреймворку или контейнеру. Вместо того чтобы приложение само управляло жизненным циклом своих компонентов, контейнер управляет этими компонентами.

Реализации IoC:

Dependency Injection (DI):
Внедрение зависимостей, когда компоненты получают свои зависимости извне, обычно через конструктор или метод.
Примеры: Spring Framework (Java), Angular (JavaScript).
Service Locator:
Компоненты получают свои зависимости из централизованного сервис-локатора, который предоставляет доступ к различным сервисам.
Примеры: Microsoft.Extensions.DependencyInjection в ASP.NET Core.




- Что такое Model-view-controller (MVC)?
MVC - это паттерн проектирования, который разделяет приложение на три основных компонента:

Model (Модель): Отвечает за представление данных и бизнес-логику.
View (Представление): Отвечает за отображение данных и взаимодействие с пользователем.
Controller (Контроллер): Отвечает за обработку пользовательских запросов, взаимодействие с моделью и обновление представления.




- Что такое Data access object (DAO)?
DAO - это паттерн проектирования, который предоставляет абстракцию для доступа к источникам данных, таким как базы данных. Он разделяет бизнес-логику от деталей доступа к данным.




- Что такое Layered architecture?
Слойная архитектура - это подход, при котором приложение разделяется на несколько слоев с определенными зонами ответственности, обычно включая Presentation Layer (представление), Business Logic Layer (бизнес-логика) и Data Access Layer (доступ к данным).




- Типовая структура Enterprise приложения. Слои, зоны ответственности  и зависимости между слоями.
Presentation Layer (Представление):
Отображение данных и взаимодействие с пользователем.
Зависит от Business Logic Layer.
Business Logic Layer (Бизнес-логика):
Обработка бизнес-правил и логики приложения.
Независим от Presentation Layer и Data Access Layer.
Data Access Layer (Доступ к данным):
Взаимодействие с базой данных или другими источниками данных.
Предоставляет данные для Business Logic Layer.




- Какие вы знаете способы интеграции программного обеспечения?
API (Application Programming Interface):
Интерфейс, который позволяет программам взаимодействовать друг с другом.
Middleware:
Промежуточный слой, обеспечивающий взаимодействие между различными программными компонентами.
Message-Oriented Middleware (MOM):
Передача сообщений между компонентами приложения.
Web Services:
Использование стандартных протоколов для обмена данными, таких как SOAP и REST.




- Типы интеграции (общий ресурс, удаленный вызов процедур, обмен сообщениями), сравнение.
Общий ресурс (Shared Resource):
Общий доступ к ресурсам, таким как база данных.
Удаленный вызов процедур (Remote Procedure Call - RPC):
Вызов удаленных процедур или методов через сеть.
Обмен сообщениями (Message Passing):
Обмен данных между компонентами через передачу сообщений.




- Расскажите о системах обмена сообщениями
Системы обмена сообщениями позволяют взаимодействовать между программами посредством передачи сообщений. Примеры включают в себя:

Message Queues:
Используются для асинхронного обмена сообщениями между компонентами.
Publish-Subscribe (Pub/Sub):
Система, где отправитель сообщения (публикатор) не указывает конкретных получателей, но сообщение доставляется всем заинтересованным подписчикам.
Event-Driven Architecture (EDA):
Система, где компоненты реагируют на события, генерируемые другими компонентами.














- Что такое высоконагруженные приложения?
Высоконагруженные приложения (High-Load Applications) - это приложения, которые обрабатывают большое количество запросов и данных в реальном времени. Эти приложения обычно сталкиваются с высокой степенью нагрузки и требуют эффективных решений для обеспечения производительности и отказоустойчивости.



- Какие проблемы бывают в высоконагруженных приложениях?
Производительность: Снижение отклика и скорости обработки запросов.
Масштабируемость: Необходимость эффективного масштабирования при увеличении нагрузки.
Отказоустойчивость: Обработка отказов и сбоев без потери данных.
Безопасность: Защита от атак и обеспечение безопасности данных.
Управление ресурсами: Эффективное использование ресурсов, таких как CPU, память и сеть.



- Что такое репликация?
Репликация - это процесс создания и поддержания точных копий данных (реплик) для обеспечения их доступности и увеличения производительности. Репликация может применяться к базам данных, файлам или другим типам данных.



- Что такое шардирование?
Шардирование - это метод горизонтального масштабирования, при котором данные разделяются на небольшие фрагменты (шарды) и распределяются по разным серверам. Это позволяет увеличивать пропускную способность и общую емкость системы.



- Что такое кеширование?
Кеширование - это процесс временного хранения результатов выполнения операций или запросов для повторного использования. Кеширование уменьшает нагрузку на систему, ускоряет ответы и повышает производительность.



- Что такое балансировка?
Балансировка - это распределение нагрузки между несколькими серверами или ресурсами для обеспечения равномерного использования ресурсов и предотвращения перегрузок.



- Какие виды балансировки Вы знаете?
Round Robin (Круговой метод): Запросы распределяются по кругу между серверами.
Least Connections (Наименьшее количество соединений): Запросы направляются к серверу с наименьшим количеством активных соединений.
Least Response Time (Наименьшее время ответа): Запросы направляются к серверу с наименьшим временем ответа.



- Что такое отказоустойчивость? Как ее можно обеспечить?
Отказоустойчивость - это способность системы продолжать нормальную работу при возникновении сбоев или отказов. Она может быть обеспечена через дублирование компонентов, использование репликации, резервирование и другие методы.



- Что такое мониторинг и алертинг?
Мониторинг: Систематическое наблюдение за работой приложения и его компонентов для выявления проблем и аномалий.
Алертинг: Уведомление о возникновении проблем или событий, требующих внимания администратора или инженера.

- Что такое микросервисы?
Микросервисы - это подход к построению архитектуры приложений, при котором приложение разбивается на небольшие, автономные и легко масштабируемые сервисы, которые могут взаимодействовать между собой.



- Когда нужны микросервисы, а когда монолиты?
Микросервисы:
Подходят для крупных, сложных систем, где каждый сервис может быть разработан, тестирован, развернут и масштабирован независимо.
Поддерживают гибкость в выборе технологий и языков программирования для каждого сервиса.
Монолиты:
Подходят для небольших и простых проектов, где отсутствует необходимость в сложной взаимосвязи между компонентами.
Обеспечивают более простую разработку и развертывание в одном монолите.



- Что такое DDD?
DDD - это методология разработки программного обеспечения, сфокусированная на понимании бизнес-домена и его отражении в структуре кода. DDD использует язык, близкий к бизнес-терминологии, и предлагает решения для моделирования сложных бизнес-процессов.



- Каковы преимущества микросервисной архитектуры?
Гибкость и масштабируемость: Каждый сервис может масштабироваться и разрабатываться независимо.
Легкость в развертывании: Возможность развертывания и обновления каждого сервиса отдельно.
Распределенная разработка: Разные команды могут работать над разными сервисами независимо.
Легкость в поддержке и модификации: Упрощенное внесение изменений и внедрение новых функций.







- Каковы недостатки микросервисной архитектуры?
Сложность управления: Требуется управление большим количеством сервисов.
Сложность взаимодействия: Работа с межсервисными взаимосвязями может быть сложной.
Сложность тестирования: Тестирование всей системы может быть трудным.
Сложность конфигурации и развертывания: Необходимость в управлении конфигурациями и оркестрации.




- Расскажите о принципы организации микросервисов
Разделение по бизнес-функционалу: Каждый сервис должен выполнять конкретную бизнес-функцию.
Автономность: Каждый сервис должен быть автономным и независимым.
Гибкая связь: Взаимосвязь между сервисами должна быть гибкой и управляемой.
Отказоустойчивость: Сервисы должны быть спроектированы с учетом возможности отказов и восстановления.




- Расскажите о типах взаимодействий микрсоервисов
HTTP/REST API: Самый распространенный протокол для взаимодействия между микросервисами.
Message Brokers: Использование сообщений для асинхронного обмена данными.
RPC (Remote Procedure Call): Вызовы удаленных процедур для взаимодействия.



- Что такое асинхронное взаимодействие?
Асинхронное взаимодействие подразумевает, что отправитель не ждет непосредственного ответа от получателя. Примеры включают в себя использование очередей сообщений и событий.



- Что такое распределенные транзакции?
Распределенные транзакции - это операции, которые воздействуют на несколько ресурсов в распределенной системе, и обеспечивают атомарность, согласованность, изолированность и долговечность (ACID).



- Что такое configuration server?
Configuration Server - это сервис, который предоставляет централизованный способ управления настройками и конфигурациями для микросервисов.



- Что такое polyglot persistance?
Polyglot Persistence - это концепция, при которой разные части приложения используют разные системы управления данными в зависимости от их требований.



- Что такое Service Discovery?
Service Discovery - это процесс обнаружения и регистрации сервисов в распределенной системе, чтобы они могли взаимодействовать друг с другом.



- Что такое Circuit Breaker?
Circuit Breaker - это паттерн, который предотвращает постоянные запросы к сервису, который может быть временно недоступен, и вместо этого возвращает заранее определенный ответ или ошибку. Это помогает избежать перегрузки и ускоряет восстановление.
